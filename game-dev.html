اصنع لعبتك الأولى ببايثون

لعبة حقيقية بنافذة وحركة وصوت لوحة مفاتيح — لا نصّاً في الطرفية. ثم نجيب عن السؤال الذي يأتي بعدها مباشرة: أيّ محرّك ألعاب أتعلّم، وهل يتحمّله جهازي؟

1 ابنِ لعبتك الأولى — خطوة خطوة

لن أعطيك لعبة جاهزة تنسخها. سنبنيها معاً في سبع خطوات، تكتب كل خطوة بيدك وتشغّلها وترى ماذا تغيّر. في نهاية كل خطوة لديك برنامج يعمل — لا نصف برنامج.

📋
قبل أن تبدأ ثبّت المكتبة بكتابة pip install pygame في طرفية VS Code، ثم أنشئ ملفاً فارغاً اسمه catch.py. سنكتب فيه من الصفر.
1

نافذة تبقى مفتوحة

اكتب هذا كاملاً في catch.py:

import pygame

pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("My First Game")

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

pygame.quit()
شغّله الآن. ستفتح نافذة سوداء بحجم 640×480، وتبقى مفتوحة حتى تضغط ✕.
لماذا الحلقة while موجودة؟

احذفها وشغّل: ستُفتح النافذة وتُغلق في لحظة. البرنامج ينتهي فيختفي كل شيء. الحلقة هي ما يُبقي اللعبة حيّة. وداخلها نسأل في كل دورة: «هل ضغط اللاعب زر الإغلاق؟» هذه أول خطوة من حلقة اللعبة: الأحداث.

2

ارسم الخلفية

＋ أضف clock بعد سطر set_caption، والسطور الثلاثة داخل الحلقة:

clock = pygame.time.Clock()          # ← جديد

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    screen.fill((18, 20, 40))        # ← جديد: املأ الشاشة بلون
    pygame.display.flip()            # ← جديد: اعرض ما رسمناه
    clock.tick(60)                   # ← جديد: 60 إطاراً في الثانية
شغّله. النافذة صارت زرقاء داكنة بدل السوداء.
لماذا سطران للرسم؟

fill يرسم على لوحة مخفيّة، وflip يعرضها دفعة واحدة. لو عرضنا كل شكل فور رسمه لرأيت وميضاً مزعجاً. احذف flip وشغّل — ستبقى النافذة سوداء رغم أن fill يعمل. هذا يثبّت الفكرة.

3

ارسم سلّة اللاعب

＋ عرّف المستطيل قبل الحلقة، وارسمه بعد fill:

player = pygame.Rect(275, 440, 90, 16)   # ← جديد: س، ص، عرض، ارتفاع

# ... وداخل الحلقة بعد screen.fill مباشرة:
    pygame.draw.rect(screen, (47, 111, 237), player, border_radius=6)
شغّله. شريط أزرق في أسفل النافذة.
انتبه: المحور ص مقلوب

في الرياضيات ص يكبر لأعلى. في الشاشات ص يكبر لأسفل: النقطة (0,0) هي الزاوية العليا اليسرى. ولهذا وضعنا السلّة عند 440 — قريباً من قاع الشاشة (480). جرّب 10 بدلاً منها لترى بنفسك.

4

حرّكها بالسهمين

فكّر قبل أن تقرأ: نريد أن نسأل في كل دورة «هل السهم الأيسر مضغوط الآن؟» ثم نغيّر player.x. حاول كتابتها بنفسك، ثم قارن.

أظهر الحل 
SPEED = 7                                 # ← قبل الحلقة

# ... داخل الحلقة، بعد حلقة الأحداث:
    keys = pygame.key.get_pressed()
    if keys[pygame.K_LEFT]:
        player.x -= SPEED
    if keys[pygame.K_RIGHT]:
        player.x += SPEED
شغّله. السلّة تتحرّك يميناً ويساراً — لكنها تخرج من الشاشة!
لماذا get_pressed لا حلقة الأحداث؟

حلقة الأحداث تخبرك بلحظة ضغط المفتاح مرة واحدة. وget_pressed تخبرك بما هو مضغوط الآن. للحركة المستمرة تحتاج الثانية، وإلا تحرّكت السلّة خطوة واحدة لكل ضغطة.

5

امنعها من الخروج

＋ سطر واحد بعد حركة السلّة مباشرة:

    player.x = max(0, min(player.x, 640 - player.width))
شغّله. السلّة تقف عند الحافّتين.
اقرأه من الداخل للخارج

min(player.x, 640 - player.width) يمنعها من تجاوز اليمين، ثم max(0, ...) يمنعها من تجاوز اليسار. حيلة من سطر واحد تُغنيك عن شرطين، وستستخدمها كثيراً في الألعاب.

6

مربّع يسقط

＋ استورد random في أعلى الملف، ثم:

block = pygame.Rect(random.randint(0, 614), -26, 26, 26)   # ← قبل الحلقة
block_speed = 4

# ... داخل الحلقة، بعد تقييد السلّة:
    block.y += block_speed
    if block.top > 480:                    # خرج من الأسفل؟
        block.y = -26                       # أعده للأعلى
        block.x = random.randint(0, 614)    # في مكان عشوائي

# ... ومع بقية الرسم:
    pygame.draw.rect(screen, (255, 171, 112), block, border_radius=4)
شغّله. مربّعات برتقالية تسقط بلا توقّف — لكنها تمرّ عبر السلّة.
لماذا يبدأ من -26؟

فوق حافّة الشاشة بمقدار حجمه، فيدخل المشهد منزلقاً بدل أن يظهر فجأة. تفصيل صغير يصنع فرقاً كبيراً في الإحساس.

7

التصادم والنقاط والمحاولات

الآن الجزء الذي يحوّله من رسوم متحرّكة إلى لعبة: قاعدة، وفوز، وخسارة. colliderect تخبرك إن كان مستطيلان متلامسين.

＋ عرّف score وlives قبل الحلقة، وبدّل شرط السقوط بهذا:

score = 0                                  # ← قبل الحلقة
lives = 3

# ... بدّل كتلة block.y السابقة بهذه:
    block.y += block_speed

    if player.colliderect(block):          # التقطه!
        score += 1
        block_speed += 0.2                 # أصعب قليلاً
        block.y = -26
        block.x = random.randint(0, 614)

    elif block.top > 480:                  # فاته!
        lives -= 1
        block.y = -26
        block.x = random.randint(0, 614)
        if lives <= 0:
            running = False                # انتهت اللعبة

＋ ولترى النقاط، عرّف الخطّ بعد clock وارسم النصّ قبل flip:

font = pygame.font.SysFont(None, 32)       # ← بعد clock

# ... قبل pygame.display.flip():
    hud = font.render(f"Score: {score}    Lives: {lives}", True, (230, 235, 255))
    screen.blit(hud, (14, 12))
شغّله. لعبة كاملة: تلتقط فتزيد نقطتك وتزداد السرعة، وتفوّت فتخسر محاولة، وبعد ثلاث إخفاقات تنتهي.

لقطة حقيقية من الكود وهو يعمل

الآن اجعلها لعبتك أنت

انتهى دوري. هذه تعديلات مرتّبة من الأسهل للأصعب — كل واحدة تعلّمك شيئاً جديداً:

  • سهل: غيّر clock.tick(60) إلى 20. الآن تعرف معنى «معدّل الإطارات».
  • سهل: احذف screen.fill(...) وشغّل. ستفهم فوراً لماذا نمسح كل إطار.
  • متوسّط: أضف مربّعاً أحمر ثانياً يخصم نقطة إن التقطته.
  • متوسّط: اجعل السلّة تضيق كلّما زادت النقاط.
  • متقدّم: احفظ أعلى نتيجة في ملف highscore.txt — تعرف الملفات من الوحدة السادسة.
  • متقدّم: حوّل المربّع الساقط إلى صنف class Block — عندها يمكنك صنع عشرة منها بسطر.
💡
هذه ليست لعبة «بسيطة» بالصدفة فيها كل ما في أي لعبة كبيرة: حلقة، إدخال، حركة، كشف تصادم، حالة (نقاط ومحاولات)، وواجهة. الألعاب الضخمة تختلف في الحجم والصقل لا في هذه الأركان.

2 محرّكات الألعاب — وماذا يناسب جهازك

💻 جهازك: MSI · Intel i7 الجيل العاشر · GTX 1650 Ti

  • معالج قويّ جداً لتطوير الألعاب — بناء المشاريع والتصريف سيكونان مريحين.
  • كرت الشاشة فئة متوسطة بذاكرة 4 غيغابايت، وهذا الرقم هو ما يحدّد سقفك مع المحرّكات الثقيلة.
  • الخلاصة: ممتاز لكل ألعاب ثنائية الأبعاد وأغلب ثلاثية الأبعاد المتوسطة، وضيّق مع ميزات Unreal 5 الحديثة.

حقيقة يجب أن تعرفها أولاً

Unity و Unreal لا يُبرمَجان ببايثون. كثيرون يكتشفون هذا متأخّرين. Unity يستخدم C#، و Unreal يستخدم C++ أو نظام العُقد المرئي Blueprints. بايثون في Unreal موجودة لكن لأتمتة المحرّر لا لبرمجة اللعبة.

هذا لا يعني أن وقتك مع بايثون ضاع — بالعكس. المفاهيم التي أتقنتها (المتغيّرات، الشروط، الحلقات، الدوال، الأصناف) هي نفسها في كل لغة. تعلّم C# بعد بايثون يستغرق أسابيع لا سنوات، لأنك تتعلّم تركيباً جديداً لا تفكيراً جديداً.

لماذا Unreal «ثقيل» على جهازك تحديداً

ميزتا Unreal 5 الكبيرتان — Nanite للتفاصيل الهندسية وLumen للإضاءة اللحظية — مصمّمتان لكروت بذاكرة 8 غيغابايت فأكثر. مع 4 غيغابايت سيعمل المحرّر لكن ببطء، وستقضي وقتك في انتظار التصريف بدل صناعة اللعبة. يمكنك تشغيله وتعطيل هاتين الميزتين، لكن حينها تكون تخلّيت عن سبب اختيارك له أصلاً.
